## Shared interface

Canonical machine-readable contract: [`rpent/skill_package/schema.json`](rpent/skill_package/schema.json), JSON Schema 2020-12, version `bounded-skills/1`. Codex2 and other robot adapters consume this same file and version. The core contains no LIBERO task suite, BDDL predicate, simulator object ID, or simulator pose. Robot-specific calibration, OSC scaling, asset paths, and template rendering belong to `robots/libero/`.

A request contains public measurement anchors, measured robot state, remaining simulation-step budget, candidates and recent receipts. Robot velocity is an interval finite difference of measured EEF positions and simulation control timestamps; it is null before a second measurement, never a fabricated zero. Optional `relations` carries measured source_id/relation/target_id triples; all IDs must resolve to public anchors. Its absence means unmeasured, not false. A decision selects **1–4 existing candidate IDs in order** for the same observation/version; it cannot supply coordinates, gains, speed, force, prompts, or an invented action. Downstream candidates are re-resolved from current measurements and screened before execution. A stale target or a new contact/verification result invalidates the unexecuted suffix. `finish`, `ask_help`, `observe`, `call_vla` and gripper contact are chunk boundaries; they cannot be blended through a stale preselected suffix. K=1 stops at each action; K=4 blends adjacent non-contact motions only.

An anchor records measurement ID, capture step, frame, cameras, source, XYZ, size, orientation and confidence. Allowed sources: RGB-D, robot proprioception, static robot geometry, or a named computation from those sources. Cache provenance includes the original capture step; cache reuse is never marked fresh. Coordinates are always **measured** in the adapter's planning frame. An unresolved value is null; no private truth may fill it. Private oracle/branch labels are stored separately, never in this request.

Destination measurements are cached before a verified payload can occlude them. While holding, destination anchors, relations and carry/lower release poses use that cache with its original capture evidence and `cached=true`; current RGB-D still supplies the collision surfaces. Empty-hand observations refresh the cache again. This assumes a stationary destination during transport and does not establish recovery from an externally moved destination.

Candidates carry consequences computed by code: minimum **hand-mesh** path clearance (m), collision result, numerical IK result, expected object width and gripper opening (m), expected simulation steps and provenance. Null means unmeasured/untested. Numerical IK failure does not prove physical impossibility. RGB-D cannot certify unseen space or entire-arm collision avoidance. The executed smoothed curve, including waypoint transitions, must be screened; screening a straight polyline alone is insufficient. Contact permits only the selected surface/part, not arbitrary surrounding penetration. Failed/unmeasured preconditions return a receipt and retain the state; they do not silently execute.

Bounded route IK starts from the captured joint sensors for each candidate. Each nearby Cartesian check continues inside a ±0.35 rad box around the preceding accepted joint solution, within the static joint limits. This local numerical search prevents accepting discontinuous elbow/wrist branches; it does not certify OSC convergence or claim infeasibility outside the box. IK caches include the incoming joint solution, and a new candidate resets to the measured joints.

Common failure phases: `perception`, `planning_unreachable`, `collision`, `contact_failure`, `verification_error`; infrastructure failures are separate. Outcomes are `success`, `failure`, `no_effect`, `unmeasured`, `rejected`, or `interrupted`. A claimed success requires the named public verifier; a sent command is not success. Two consecutive no_effect/failed repeats remove that same action until a measured scene change. execution_error excludes the same action for the next three decisions. Keep counts in existing candidate metadata; use one canonical serializer.

Held-object centres and bounds are normalised from the current self-filtered payload surface before both recovery-change accounting and receipt comparisons. Requests and post-action measurements use that same estimator. Switching between a raw semantic-mask centre and the cleaned payload centre is not physical progress and cannot keep an unchanged observation action available.

Last observed entity positions persist across temporary occlusion. Re-detecting a known entity at the same position neither resets failed-action counts nor counts as observation progress. A first measured identity or measured displacement can still supply progress.

## Smooth executor

Use **piecewise quintic splines with shared nonzero waypoint velocities and zero jerk at each original waypoint**, implemented with existing NumPy/SciPy. Ruckig is MIT and a viable alternative, but no new dependency is needed here; this choice allows inspection and re-screening of the exact blended Cartesian curve. Do not describe the result as globally minimum jerk: each original segment contains three quintic spans, with two internal knots providing enough degrees of freedom to constrain p/v/a/jerk at both ends. Internal span junctions are C4; original waypoints and rest boundaries are C3. `Trajectory.waypoint_times` identifies action waypoints; spline spans are not additional decisions. Opposite directions/contact boundaries use zero through velocity. Polynomial extrema bound velocity/acceleration/jerk; increase duration until limits hold.

Run at 20 Hz. Translate **vector** desired displacement into Panda OSC commands (`translation_action_scale_m=0.05`, `rotation_action_scale_rad=0.50`, verified in current Panda tests); do not independently clip XYZ. Feedback corrections are vector bounded and tracked separately from feedforward. Serialize desired/actual pose, velocity, acceleration, jerk, tracking error, collisions and stop causes at every control tick. Limits govern generated references; observed tracking metrics remain measured, not assumed.

Translation and rotation tangents are computed independently in their configured coordinate groups. A leg with no movement in one group gives that group zero through velocity, so an in-place wrist rotation does not inherit a translational tangent. The LIBERO controller can command one control sample ahead on the same screened curve (`reference_lead_s=0.05`, capped at one 20 Hz tick). This compensates tracking lag without extrapolating outside that curve. Traces retain both the timed reference used for tracking-error measurement and the actual `command_reference`; braking, collision margins and force limits remain separate.

Panda adapter starts conservatively at translation speed 0.15 m/s, acceleration 0.5 m/s², jerk 2.0 m/s³; rotation 0.4 rad/s, 1.0 rad/s², 4.0 rad/s³. These simulation development settings are below the Panda-era **libfranka 0.9.2** published rate limits (translation 2.0 m/s before packet-loss margin, 13 m/s², 6500 m/s³; rotation 2.5 rad/s before margin, 25 rad/s², 12500 rad/s³). Primary source: `https://raw.githubusercontent.com/frankaemika/libfranka/0.9.2/include/franka/rate_limiting.h`, retrieved SHA256 `ac27bb0e48b83f1c9714f544ad1a921fb8101af9b697d354580743da1d8805ad`. The historical control-parameter documentation URL currently returns 404, so use this pinned implementation reference. These settings are not real-robot approval and do not increase gripper force. Pin configuration/source hashes in each run.

Stop smoothly at chunk end/contact boundary or when public tracking error exceeds 3 cm. Braking starts from the latest measured pose and estimated velocity/acceleration/jerk, uses bounded acceleration/jerk, and is screened against current public geometry. If continuation is unavailable, execute the already screened braking tail; do not send a one-tick zero-velocity jump. Native environment termination/truncation may require immediate end of simulation commands and is recorded separately.

Braking uses continuous trapezoidal jerk with 5 ms internal polynomial knots, sampled into the same 20 Hz OSC commands. It preserves the initial measured derivatives and returns inherited jerk toward zero over a short internal knot before nominal bounded braking. No snap limit is claimed. Exact polynomial extrema check speed, acceleration and jerk; an inherited overspeed/acceleration is recorded rather than instantaneously zeroed. Every resulting stop still needs the complete measured-scene collision and IK screen. This avoids rejecting the compact stop family and falling back to a long outward acceleration-cancellation route.

Braking retains useful inherited deceleration: it checks shorter C3 quintic stops before the convergent acceleration-cancellation stop. Both use the same derivative bounds and full route screen. Cancelling deceleration first can lengthen the stop enough to leave the reachable workspace; a rejected stopping route is never executed unchecked.

With outward or mixed-axis acceleration, the executor also fits a free-endpoint stop using two cubic acceleration ramps and a constant-acceleration interval. Their integrals are quintic position pieces with continuous p/v/a/j. Durations and the shared braking vector enforce zero final velocity; exact polynomial extrema check the configured vector bounds before full route screening. An unsuccessful numerical fit supplies no permission to move.

The LIBERO adapter now records one public sensor stream across motion, gripper and VLA controls. Four consecutive 20 Hz samples supply the next route's initial translational/angular v/a/j automatically. A missing/stale stream is labeled `unmeasured_rest_reference`, not measured zero. Inherited derivatives that cannot satisfy nominal limits use a continuous braking prefix before the new route; that prefix and the suffix are screened together. This source wiring has CPU evidence; physical retarget evidence is reported separately per snapshot.

Async API uses `submit(observation_id, candidates, remaining_s)` and a nonblocking future. Trigger when chunk time remaining is below Codex2's measured decision-latency estimate; at most one pending request. The estimate is injectable and logged, not invented as a measured value. Responses bind to observation/candidate IDs and revision; changed geometry/contact discards the suffix. No next chunk ⇒ bounded deceleration. All semantic choices remain with the model/oracle.

An in-motion request keeps its original measured robot state, budget, receipts and observation ID. Its decision may cross only the just-completed, successful free-motion chunk: the endpoint must still match that chunk, all anchors must remain within 1 cm with visible/cached provenance, and the selected routes are rechecked against current public geometry, failure memory and remaining budget. Contact, failed motion, new collision/unreachable evidence or insufficient budget discards it. Endpoint revalidation is recorded separately; it does not rewrite the earlier observation or its predicted costs. Actual endpoint latency, useful overlap and discarded-prefetch rates remain required physical evidence.
