# Bounded skill package v3 — 2026-10-18

Owner: Codex3. This contract implements the user's **10/16 05:45 PDT** direction; the 10/14 pause and old v5 freeze gates are retired. No model training is authorized in this round. This is a development specification, not evidence of physical qualification. Existing confirmation-state exclusions remain permanent.

## Shared interface

Canonical machine-readable contract: [`rpent/skill_package/schema.json`](rpent/skill_package/schema.json), JSON Schema 2020-12, version `bounded-skills/3`. Codex2 and other robot adapters consume this same file and version. The core contains no LIBERO task suite, BDDL predicate, simulator object ID, or simulator pose. Robot-specific calibration, OSC scaling, asset paths, and template rendering belong to `robots/libero/`.

A request contains public measurement anchors, measured robot state, remaining simulation-step budget, candidates and recent receipts. Robot velocity is an interval finite difference of measured EEF positions and simulation control timestamps; it is null before a second measurement, never a fabricated zero. Optional `relations` carries measured source_id/relation/target_id triples; all IDs must resolve to public anchors. Its absence means unmeasured, not false. A decision selects **1–4 existing candidate IDs in order** for the same observation/version; it cannot supply coordinates, gains, speed, force, prompts, or an invented action. Downstream candidates are re-resolved from current measurements and screened before execution. Only `observe`, `call_vla`, `finish`, and `ask_help` statically terminate a chunk. Every other skill may have a suffix referencing already measured anchors or fixed quantities. Each step checks its expected receipt; failed, missing or contradicted evidence stops smoothly and discards the remaining suffix. Successful contact does not itself require another model decision. K=1 returns after one action; K=4 blends adjacent free motions and retains public measurement checkpoints at contact.

### Compact infeasibility and in-flight prefix (v3)

A candidate whose current measured sweep collides (`collision=true`) or whose numerical IK fails (`ik_reachable=false`) keeps its ID, skill, parameters and failure counts, but replaces the full consequence with `{collision, ik_reachable, screen_scope:"blocked_at_current_prefix"}`. Its history and expected receipt are omitted. Unknown or conditional feasibility retains the full representation. This preserves future actions: an initially blocked lift can become feasible after a selected approach/closure. No task goal, oracle answer, BDDL predicate or test outcome participates in this compression. Candidate count and order are unchanged. `prefix_context` and the executor recompute full consequences from the chosen predecessor state before execution; a blocker is never treated as permission to move. Diagnostics retain the full measured blocking reason outside model input. Codex2 may use a reversible compact presentation with shared column legends, short selection codes and six decimal places for displayed numbers (`round(value, 6)`; at most 0.0000005 absolute error in each field's original units). The validated source request, planning, collision/IK checks, IDs and private labels keep full-precision values; presentation rounding must never feed back into them. Source requests retain the last three detailed receipts; no goal-dependent history filtering is added.

Every request includes `execution_prefix`: null at an ordinary decision boundary, otherwise the uncompleted committed steps (`id/skill/parameters`), their source observation/revision, expected-receipt assumptions, and `predicted_state` (robot, anchors, remaining simulation budget). The request's top-level robot/anchors remain measurements at capture time. Only `predicted_state` is the conditional endpoint; its poses must not be described as new observations. The next selection begins **after** those committed steps, not by executing them again. Source `committed_candidate_ids(request)`, prefix contexts, selection validation and oracle legal labels exclude those committed IDs and matching `(skill, parameters)` identities, including regenerated IDs. A subsequent fresh observation may expose a repeated relative action again. In-flight relative moves use the endpoints of their already screened trajectory, not another full displacement from the intermediate pose.

The current asynchronous implementation prefetches through free-motion chunks. The execution thread freezes public observations, committed endpoints and geometry; the worker never queries the simulator. A result is adopted only after that same source chunk completes successfully, its measured endpoint agrees with the prediction, and current geometry, payload identity, remaining budget and newly selected routes pass revalidation. A failed/interrupted commitment discards the prefetched suffix. Contact chunks still execute multiple selected steps but retain measured checks before preparing a subsequent decision.

An anchor records measurement ID, capture step, frame, cameras, source, XYZ, size, orientation and confidence. Allowed sources: RGB-D, robot proprioception, static robot geometry, or a named computation from those sources. Cache provenance includes the original capture step; cache reuse is never marked fresh. Coordinates are always **measured** in the adapter's planning frame. An unresolved value is null; no private truth may fill it. Private oracle/branch labels are stored separately, never in this request.

LIBERO measurement rendering can use `rgbd_no_msaa_v1`: a temporary single-sample framebuffer supplies the paired RGB/depth images, avoiding multisample depth blends across foreground/background edges. It restores the normal framebuffer and rendering settings after every call, including errors; raw policy observations retain their original rendering. The bounded feasibility runner enables this measurement path by default and records `public-rgbd-single-sample/1` in `measurement_render.json`; setting the configuration flag false retains the legacy path. Geometry coordinates can change; schema, collision clearance, actuator limits and action budgets do not. This is a sensor-path correction, not a task-success claim.

Destination measurements are cached before a verified payload can occlude them. While holding, destination anchors, relations and carry/lower release poses use that cache with its original capture evidence and `cached=true`; current RGB-D still supplies the collision surfaces. Empty-hand observations refresh the cache again. The LIBERO adapter also retains measured table/cabinet/stove/microwave bodies, top surfaces and area anchors through temporary occlusion during empty-hand contact, with their original capture evidence. This exemption does not retain unmeasured movable objects or drawer/door poses. These caches assume stationary destinations and do not establish recovery from an externally moved destination.

Candidates carry consequences computed by code: minimum **hand-mesh** path clearance (m), collision result, numerical IK result, expected object width and gripper opening (m), expected simulation steps and provenance. Null means unmeasured/untested. Numerical IK failure does not prove physical impossibility. RGB-D cannot certify unseen space or entire-arm collision avoidance. The executed smoothed curve, including waypoint transitions, must be screened; screening a straight polyline alone is insufficient. Contact permits only the selected surface/part, not arbitrary surrounding penetration. Failed/unmeasured preconditions return a receipt and retain the state; they do not silently execute.

Bounded route IK starts from the captured joint sensors for each candidate. A braking tail's IK starts from the current post-motion joint and EEF measurements and screens their corrective sweep to the continuing command reference, retaining the original captured collision surfaces, payload and clearance baselines. Each nearby Cartesian check continues inside a ±0.35 rad box around the preceding accepted joint solution, within the static joint limits. This local numerical search prevents accepting discontinuous elbow/wrist branches; it does not certify OSC convergence or claim infeasibility outside the box. IK caches include the incoming joint solution, and a new candidate resets to the measured joints.

After motion with a previously verified held object, fresh visible RGB-D bounds are compared with the prior measured bounds transported by the observed EEF rigid transform. If the bounds are separated by more than the existing 15 mm holding-coupling tolerance, the action returns `failure` / `contact_failure` / `public_hold_lost`, marks that anchor `held=false`, and clears its attachment and contact references before generating new candidates. Occluded or stale measurements cannot assert loss. The comparison accounts for wrist rotation and uses public measurements. It checks each selected motion endpoint, including each action passage within a blended chunk. It does not claim continuous RGB-D holding evidence between these checkpoints. A detected loss ends the chunk before any remaining contact action.

Initial lift verification uses that same transported-bounds comparison, a fresh measured lower-bound rise of at least 3 cm, and calibrated nonempty gripper opening. The contact reference retains the complete measured EEF pose after closure, so wrist rotation is included. Visible segmentation centres can change as a surface is uncovered; their displacement remains diagnostic and does not substitute for a material-point track. The 15 mm bounds gap is unchanged. Stale/missing paired motion evidence is `unmeasured`, not success. This endpoint evidence does not establish continuous holding at every intermediate instant or replace private sustained-grasp scoring.

Common failure phases: `perception`, `planning_unreachable`, `collision`, `contact_failure`, `verification_error`; infrastructure failures are separate. Outcomes are `success`, `failure`, `no_effect`, `unmeasured`, `rejected`, or `interrupted`. A claimed success requires the named public verifier; a sent command is not success. Two consecutive no_effect/failed repeats remove that same action until a measured scene change. For anchored contact with no measured object progress or missing object-motion evidence, reactivation requires a measured change of that source anchor; unrelated entity-centre drift does not clear its count. Collision failures can reactivate after any measured scene change because an obstacle may have moved. execution_error excludes the same action for the next three decisions. Keep counts in existing candidate metadata; use one canonical serializer.

`nudge` and `rotate_wrist` with a contact `anchor_id` refresh public measurements and verify their receipt before a selected suffix continues. They are not static chunk boundaries. Contact chunks currently prepare async decisions only after their measurements; free-space variants remain eligible for in-motion prefetch and blending.

A held-object `nudge` registers the measured moving payload surface in world coordinates. The stationary contact-target cloud is empty for a held object by design and cannot supply this reference. The private upper-bound selector can choose an existing screened 1–2 cm upward nudge when transport and alignment are both unavailable, then reobserve; it creates no additional motion option.

Held-object centres and bounds are normalised from the current self-filtered payload surface before both recovery-change accounting and receipt comparisons. Requests and post-action measurements use that same estimator. Switching between a raw semantic-mask centre and the cleaned payload centre is not physical progress and cannot keep an unchanged observation action available.

Current non-fixture instance masks are depth-component cleaned before grasp planning as well as after contact. Within the clean mask's measured 3-D extent, connected current RGB-D samples separated by at most 3 mm may complete a curved seam that linear boundary extrapolation misses. This uses the same robot-filtered pixels as route screening. Points outside that measured extent, disconnected surfaces and rejected mask components remain obstacles; no metric halo is subtracted. Boundary evidence records the extent and recovered pixel count. The model-facing schema is unchanged.

Within a measured moving-payload extent, local plane completion can use the observed pixel spacing at a sparse corner: two independent image axes must each supply two interior samples, and the next pixel must lie within twice their measured spacing. The fitted plane still requires two measured tangent directions and at most 1 mm residual, and the pre-lift stationary-scene veto still applies. A straight mask edge cannot acquire this spacing allowance. This addresses grazing image sampling; it does not reduce collision clearance or relabel a nearby point solely by distance.

Last observed entity positions persist across temporary occlusion. Re-detecting a known entity at the same position neither resets failed-action counts nor counts as observation progress. A first measured identity or measured displacement can still supply progress.

An occluded active contact retains its already measured anchor and committed contact plan, marked cached with the original capture step. It does not trigger a new contact fit from cached bounds. If the entity or its committed measurement is unavailable, anchor-dependent actions are omitted; the request never contains a dangling anchor reference.

Current RGB-D can refine the EEF-predicted handle surface. If the unconstrained rigid fit exceeds its displacement/rotation limits, a fallback fits only translation along the independently measured contact normal. It retains the existing 15 mm displacement bound and the requirement for at least 40 points and half the predicted surface within 8 mm of current depth, and must improve the median residual. No rotation or tangential correction is supplied by this fallback. The unchanged 1 mm contact-pixel association and 4 mm hand sweep checks still follow; a fitted pose alone never removes scene points.

Tracked handles retain their measured surface extent during depth recovery and cross-view matching, with the existing 1 mm association allowance. Smooth depth continuity through an attachment is insufficient to label its backing door, cabinet or table as handle pixels. A newly observed handle silhouette requires an independent current handle measurement; cross-view association can then use that current measured extent. Missing evidence remains unmeasured. The schema and contact-motion threshold do not change.

A measured thin panel can supply a surface-contact option even when no handle is visible. Its normal comes from the RGB-D plane, oriented using the measured parent or robot position; the fingertip contact point lies on the measured surface. Both symmetric wrist orientations are checked, since the nearest orientation can reach a joint limit. Vertical or tilted panels offer direct and overhead routes, each screened as a complete smooth approach. These are contact options, not verified grasps. The private oracle may select an already available, uniquely identified child panel; it cannot create a contact pose from a task predicate.

Microwave door measurements retain their accepted raw clouds in the same scene and per-camera stores as drawer measurements. A fitted door bound or privately saved measurement artifact alone does not supply contact geometry to the executor. Rejected or ambiguous door views supply no such cloud.

## Conditional chunks and private oracle labels (v2)

The 10/17 23:10 PDT amendment replaces decision-time contact cutoffs with execution-time guards. Motion checks endpoint position and orientation; closure checks the measured opposing-width range (15 mm fit/pad allowance, excluding empty jaws); lift checks fresh measured lower-bound rise ≥3 cm and verified holding; transport retains its held anchor; release checks open jaws and no held anchor. Contact nudge also requires public measured progress. Before executing a chunk, the adapter freezes the current public contact surfaces of its referenced anchors. If a later visible centre disagrees with prediction, fresh RGB-D is checked against that original surface translated by the expected contact prefix; identity overlap and the existing three-axis 1 cm displacement bound must all pass. Predicted motion alone never authorizes the suffix. The existing domain verifier remains required. Native environment success takes precedence, while missing guard evidence remains explicit in `expectation_checks`.

`MeasuredSkillAdapter.prefix_context(request, prefix)` produces the schema's public `prefix_context`: original observation/revision, exact ordered prefix, `predicted_robot`, successor candidates with re-computed consequences, and the predecessor checks assumed to pass. This is a lazy public operation, independent of any oracle selection. Predicted states are explicitly not sensor measurements. The model consumer may compile its `legal_by_prefix` metadata from these contexts; it must not narrow legality using private oracle labels. A successor whose route requires a not-yet-held object has `screen_scope=conditional_on_prefix` in the root candidate catalog and becomes screened only in a prefix that supplies the measured-anchor grasp. A selected chunk is planned this way and each step is re-resolved against actual measurements before execution. A fresh unexplained anchor displacement over 1 cm discards its suffix. No new anchor, unseen extent or hidden coordinate is invented.

Public prefix prediction carries the measured object cloud in the predicted gripper frame after expected closure/lift. Subsequent hand/payload sweeps use the predicted jaw opening, object transform and route's IK continuation, not the initial empty-hand state. This conditional attachment cannot assert runtime holding: actual lift still requires fresh RGB-D and aperture evidence. The code retains rest checkpoints for contact while adjacent free motions use a single smooth curve; an intermediate waypoint error triggers a screened smooth brake before the suffix is executed.

A wrist scan clears active contact after measured withdrawal, but retains an existing released surface's stationary identity for further screened withdrawal. Motion distance alone does not prove separation from a tall panel. Only matching current RGB-D may populate that contact surface; it is never attached to the moving hand. A new descent replaces the reference. Palm/scene collision checks and IK remain required.

Prefix screening retains the original robot-filtered scene pixels and instance pixels separately from their sampled collision clouds. It removes all stationary copies of moved/attached instances in one pass before sampling the remaining scene. Independently sampled scene and target clouds can retain different representatives of the same surface, so subtracting them afterwards would invent self-obstacles. Only exact measured instance membership (1 micrometre numeric tolerance) is removed; nearby nonmember pixels retain the existing 4 mm collision clearance. These internal geometry inputs are not new model-visible fields.

The same schema defines a separate **private** `oracle_labels` message with request SHA256 and per-position `prefix`, `legal`, `selected`, `rule_acceptable`, `measured_success`, `measured_failure`, `judge`, `evidence`. The LIBERO oracle enumerates the next task-progress phase for each unsatisfied original-task goal. Its rules admit all screened approaches to the same source and all same-direction contact increments no longer than the selected increment. These are rule-acceptable options, not measured successes. Other legal options are negative under these explicit rules. Later positions use the predicted state conditional on their own predecessor checks; they never reuse the initial state's answer. Fork evidence must match the same request/state/prefix before modifying the measured sets.

Private judge `libero-private-task-progress-rules/4` returns an existing nonempty prefix when a predicted contact successor is blocked and would otherwise add a refresh. The executor already measures and checks each completed step before the next decision. This avoids spending an additional no-motion observation and its failure count merely to repeat those checks. A genuinely missing source/target measurement still selects an observation; an obstruction confirmed in the current measured state retains the existing recovery. Public candidate screening and receipt conditions are unchanged.

Final labels are `(rule_acceptable ∪ measured_success) − measured_failure`. An overlap between measured success and failure is rejected. `validate_labels` binds the hash, observation, revision, ordered selected path and public candidate IDs. These messages are written to `private_oracle_labels.jsonl`; request/state/criteria never contain labels, judge, task predicates or their evidence. Codex2's MODEL_IO_SPEC uses these exact five label field names and the sole shared schema.

Smoothness acceptance requires continuous position, velocity and acceleration with bounded jerk; jerk continuity is not required. The existing C3 implementation remains. Report acceleration jumps at joins separately for translation/rotation and maximum reference jerk divided by its configured limit; measured jerk and tracking error remain separate. Keep current conservative limits until category wall-time and simulation-step-limit evidence demonstrates a speed-related timeout. Versioned configuration comments must justify any later change.

## Smooth executor

Use **piecewise quintic splines with shared nonzero waypoint velocities and zero jerk at each original waypoint**, implemented with existing NumPy/SciPy. Ruckig is MIT and a viable alternative, but no new dependency is needed here; this choice allows inspection and re-screening of the exact blended Cartesian curve. Do not describe the result as globally minimum jerk: each original segment contains three quintic spans, with two internal knots providing enough degrees of freedom to constrain p/v/a/jerk at both ends. Internal span junctions are C4; original waypoints and rest boundaries are C3. `Trajectory.waypoint_times` identifies action waypoints; spline spans are not additional decisions. Opposite directions/contact boundaries use zero through velocity. Polynomial extrema bound velocity/acceleration/jerk; increase duration until limits hold.

Run at 20 Hz. Translate **vector** desired displacement into Panda OSC commands (`translation_action_scale_m=0.05`, `rotation_action_scale_rad=0.50`, verified in current Panda tests); do not independently clip XYZ. Feedback corrections are vector bounded and tracked separately from feedforward. Serialize desired/actual pose, velocity, acceleration, jerk, tracking error, collisions and stop causes at every control tick. Limits govern generated references; observed tracking metrics remain measured, not assumed.

Translation and rotation tangents are computed independently in their configured coordinate groups. A leg with no movement in one group gives that group zero through velocity, so an in-place wrist rotation does not inherit a translational tangent. The LIBERO controller can command one control sample ahead on the same screened curve (`reference_lead_s=0.05`, capped at one 20 Hz tick). This compensates tracking lag without extrapolating outside that curve. Traces retain both the timed reference used for tracking-error measurement and the actual `command_reference`; braking, collision margins and force limits remain separate.

Panda adapter starts conservatively at translation speed 0.15 m/s, acceleration 0.5 m/s², jerk 2.0 m/s³; rotation 0.4 rad/s, 1.0 rad/s², 4.0 rad/s³. These simulation development settings are below the Panda-era **libfranka 0.9.2** published rate limits (translation 2.0 m/s before packet-loss margin, 13 m/s², 6500 m/s³; rotation 2.5 rad/s before margin, 25 rad/s², 12500 rad/s³). Primary source: `https://raw.githubusercontent.com/frankaemika/libfranka/0.9.2/include/franka/rate_limiting.h`, retrieved SHA256 `ac27bb0e48b83f1c9714f544ad1a921fb8101af9b697d354580743da1d8805ad`. The historical control-parameter documentation URL currently returns 404, so use this pinned implementation reference. These settings are not real-robot approval and do not increase gripper force. Pin configuration/source hashes in each run.

Stop smoothly at chunk end, measured contact interruption or when public tracking error exceeds 3 cm. An interrupted smooth motion brakes from its last actually commanded reference pose and velocity/acceleration/jerk in the same rotation-vector frame. Measured feedback derivatives remain diagnostic; resetting the reference to them would introduce a jump. The corrective sweep from the measured pose to that reference and the complete tail require the public geometry and current-joint IK screen. An external-control handoff with no preceding smooth reference uses the measured pose and estimated derivatives instead. A rejected tail is reported explicitly and is not called a smooth stop. Native environment termination/truncation may require immediate end of simulation commands and is recorded separately.

Braking uses continuous trapezoidal jerk with 5 ms internal polynomial knots, sampled into the same 20 Hz OSC commands. It preserves the supplied initial derivatives and returns inherited jerk toward zero over a short internal knot before nominal bounded braking. No snap limit is claimed. Exact polynomial extrema check speed, acceleration and jerk; an inherited overspeed/acceleration is recorded rather than instantaneously zeroed. Every resulting stop still needs the complete measured-scene collision and IK screen. This avoids rejecting the compact stop family and falling back to a long outward acceleration-cancellation route.

Braking retains useful inherited deceleration: it checks shorter C3 quintic stops before the convergent acceleration-cancellation stop. Both use the same derivative bounds and full route screen. Cancelling deceleration first can lengthen the stop enough to leave the reachable workspace; a rejected stopping route is never executed unchecked.

With outward or mixed-axis acceleration, the executor also fits a free-endpoint stop using two cubic acceleration ramps and a constant-acceleration interval. Their integrals are quintic position pieces with continuous p/v/a/j. Durations and the shared braking vector enforce zero final velocity; exact polynomial extrema check the configured vector bounds before full route screening. An unsuccessful numerical fit supplies no permission to move.

The LIBERO adapter records one public sensor stream across motion, gripper and VLA controls. An immediately adjacent successful smooth motion retains the previous rest reference's pose and zero reference derivatives, rather than replacing them with feedback-lag derivatives. This continuation requires the same control index and unchanged sensor state, and the preceding measured endpoint must be within tolerance. The corrective sweep from the actual robot pose to that reference is screened along with the new curve; OSC continues to use current sensors. An intervening gripper, VLA or other control invalidates this reference continuation. Otherwise four consecutive 20 Hz samples supply the next route's initial translational/angular v/a/j automatically. A missing/stale stream is labeled `unmeasured_rest_reference`, not measured zero. Inherited derivatives that cannot satisfy nominal limits use a continuous braking prefix before the new route. That prefix must pass screening before planning its retarget suffix; the complete prefix and suffix are then screened together. Swept samples are checked incrementally, retaining the same spacing and forced endpoint IK check, so a failed prefix does not require expanding its unreachable future. A wrist scan also requires measured endpoint error within the configured motion tolerance; reaching the reference's final timestamp alone cannot report arrival. This source wiring has CPU evidence; physical retarget evidence is reported separately per snapshot. Reference continuity across measured-state braking or external-control handoffs is audited separately and is not certified by nominal spline metrics.

Async API uses `submit(observation_id, candidates, remaining_s)` and a nonblocking future. Trigger when chunk time remaining is below Codex2's measured decision-latency estimate; at most one pending request. The estimate is injectable and logged, not invented as a measured value. Responses bind to observation/candidate IDs and revision; changed geometry/contact discards the suffix. No next chunk ⇒ bounded deceleration. All semantic choices remain with the model/oracle.

An in-motion request keeps its original measured robot state, budget, receipts and observation ID. Its decision may cross only the just-completed, successful free-motion chunk: the endpoint must still match that chunk, all anchors must remain within 1 cm with visible/cached provenance, and the selected routes are rechecked against current public geometry, failure memory and remaining budget. Contact, failed motion, new collision/unreachable evidence or insufficient budget discards it. Endpoint revalidation is recorded separately; it does not rewrite the earlier observation or its predicted costs. Actual endpoint latency, useful overlap and discarded-prefetch rates remain required physical evidence.

## Private oracle and feasibility protocol

Oracle may inspect original BDDL task rules and simulator truth to **select existing public candidate IDs** and diagnose labels. It may not replace anchor coordinates, collision evidence, relation estimates or receipts with truth. Upper-bound skill-package arm has call_vla disabled and no vla_task. Truth-based selection and public execution are distinct files/interfaces.

If full transport and alignment are blocked, the oracle can select an existing screened 1–2 cm lift. If that lift is also blocked, it can select a screened planar nudge that reduces the measured distance to the destination. The recovery does not change candidate geometry or collision margins; all remaining actions and observations retain their normal eligibility.

Private task-progress rules version 3 distinguish predicted contact from measured failure. When a later step's predicted fixture nudge, wrist turn or push is blocked, the oracle selects an existing stationary refresh before releasing or withdrawing from that contact. It does not close and immediately reopen the hand solely because a conditional route is blocked. Once the same obstruction is measured at a fresh decision boundary, the existing open-and-reapproach recovery remains available. This changes private option selection and labels, not public candidates, collision checks, receipts or the shared schema.

Development trial identities are original LIBERO task/init states cleared against existing confirmation registries; all conditions share exact initial state and total 10,000-simulation-step budget. Start 20 per category: bowl/plate/box/cup grab-place, drawer open/close, stove on/off, microwave, container insertion. Expand to 100 only after inspecting the 20 results and repairing concrete gaps. Keep every failure, including failures in early development.
