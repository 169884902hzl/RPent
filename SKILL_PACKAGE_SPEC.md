## Shared interface

Canonical machine-readable contract: [`rpent/skill_package/schema.json`](rpent/skill_package/schema.json), JSON Schema 2020-12, version `bounded-skills/6`. Codex2 and other robot adapters consume this same file and version. The core contains no LIBERO task suite, BDDL predicate, simulator object ID, or simulator pose. Robot-specific calibration, OSC scaling, asset paths, and template rendering belong to `robots/libero/`.

A request contains public measurement anchors, measured robot state, remaining simulation-step budget, candidates and recent receipts. Robot velocity is an interval finite difference of measured EEF positions and simulation control timestamps; it is null before a second measurement, never a fabricated zero. Optional `relations` carries measured source_id/relation/target_id triples; all IDs must resolve to public anchors. Its absence means unmeasured, not false. A decision selects **1–4 existing candidate IDs in order** for the same observation/version; it cannot supply coordinates, gains, speed, force, prompts, or an invented action. Downstream candidates are re-resolved from current measurements and screened before execution. Only `observe`, `call_vla`, `finish`, and `ask_help` statically terminate a chunk. Every other skill may have a suffix referencing already measured anchors or fixed quantities. Each step checks its expected receipt; failed, missing or contradicted evidence stops smoothly and discards the remaining suffix. Successful contact does not itself require another model decision. K=1 returns after one action; K=4 blends adjacent free motions and retains public measurement checkpoints at contact.

The candidate catalog's array order has no semantic meaning and is not a ranking. Model-side presentation may permute candidates while retaining IDs and their complete associated fields. This does not change legal or acceptable set membership. The selected decision's ID order is the execution order and remains meaningful. The source does not reorder its catalog for augmentation.

### Compact infeasibility and in-flight prefix (v3)

A candidate whose current measured sweep collides (`collision=true`) or whose numerical IK fails (`ik_reachable=false`) keeps its ID, skill, parameters and failure counts, but replaces the full consequence with `{collision, ik_reachable, screen_scope:"blocked_at_current_prefix"}`. Its history and expected receipt are omitted. Unknown or conditional feasibility retains the full representation. The catalog retains these IDs for diagnostics. A frozen known blocker remains unavailable to the decoder until a fresh request measures its feasibility again. No task goal, oracle answer, BDDL predicate or test outcome participates in this compression. Candidate count and order are unchanged. `prefix_context` and the executor recompute full consequences from the chosen predecessor state before execution; a blocker is never treated as permission to move. Diagnostics retain the full measured blocking reason outside model input. Codex2 may use a reversible compact presentation with shared column legends, short selection codes and six decimal places for displayed numbers (`round(value, 6)`; at most 0.0000005 absolute error in each field's original units). The validated source request, planning, collision/IK checks, IDs and private labels keep full-precision values; presentation rounding must never feed back into them. Source requests retain the last three detailed receipts; no goal-dependent history filtering is added.

Every request includes `execution_prefix`: null at an ordinary decision boundary, otherwise the uncompleted committed steps (`id/skill/parameters`), their source observation/revision, expected-receipt assumptions, and `predicted_state` (robot, anchors, remaining simulation budget). The request's top-level robot/anchors remain measurements at capture time. Only `predicted_state` is the conditional endpoint; its poses must not be described as new observations. The next selection begins **after** those committed steps, not by executing them again. Source `committed_candidate_ids(request)`, prefix contexts, selection validation and oracle legal labels exclude those committed IDs and matching `(skill, parameters)` identities, including regenerated IDs. A subsequent fresh observation may expose a repeated relative action again. In-flight relative moves use the endpoints of their already screened trajectory, not another full displacement from the intermediate pose.

The current asynchronous implementation prefetches through free-motion chunks. The execution thread freezes public observations, committed endpoints and geometry; the worker never queries the simulator. A result is adopted only after that same source chunk completes successfully, its measured endpoint agrees with the prediction, and current geometry, payload identity, remaining budget and newly selected routes pass revalidation. A failed/interrupted commitment discards the prefetched suffix. Contact chunks still execute multiple selected steps but retain measured checks before preparing a subsequent decision.

An anchor records measurement ID, capture step, frame, cameras, source, XYZ, size, orientation and confidence. Allowed sources: RGB-D, robot proprioception, static robot geometry, or a named computation from those sources. Cache provenance includes the original capture step; cache reuse is never marked fresh. Coordinates are always **measured** in the adapter's planning frame. An unresolved value is null; no private truth may fill it. Private oracle/branch labels are stored separately, never in this request.

LIBERO measurement rendering can use `rgbd_no_msaa_v1`: a temporary single-sample framebuffer supplies the paired RGB/depth images, avoiding multisample depth blends across foreground/background edges. It restores the normal framebuffer and rendering settings after every call, including errors; raw policy observations retain their original rendering. The bounded feasibility runner enables this measurement path by default and records `public-rgbd-single-sample/1` in `measurement_render.json`; setting the configuration flag false retains the legacy path. Geometry coordinates can change; schema, collision clearance, actuator limits and action budgets do not. This is a sensor-path correction, not a task-success claim.

Destination measurements are cached before a verified payload can occlude them. While holding, destination anchors, relations and carry/lower release poses use that cache with its original capture evidence and `cached=true`; current RGB-D still supplies the collision surfaces. Empty-hand observations refresh the cache again. The LIBERO adapter also retains measured table/cabinet/stove/microwave bodies, top surfaces and area anchors through temporary occlusion during empty-hand contact, with their original capture evidence. This exemption does not retain unmeasured movable objects or drawer/door poses. These caches assume stationary destinations and do not establish recovery from an externally moved destination.

Candidates carry consequences computed by code: minimum **hand-mesh** path clearance (m), collision result, numerical IK result, expected object width and gripper opening (m), expected simulation steps and provenance. Null means unmeasured/untested. Numerical IK failure does not prove physical impossibility. RGB-D cannot certify unseen space or entire-arm collision avoidance. The executed smoothed curve, including waypoint transitions, must be screened; screening a straight polyline alone is insufficient. Contact permits only the selected surface/part, not arbitrary surrounding penetration. Failed/unmeasured preconditions return a receipt and retain the state; they do not silently execute.

For a measured thin horizontal surface, `move_to` approaches also select a contact patch: `above` retains the default screened patch; `front`, `left` and `right` select a patch on the corresponding measured camera-axis side. Each branch passes the same closure, complete route collision and IK checks; an unavailable branch is omitted. The chosen patch is committed through subsequent descent in both prefix prediction and execution. Contact branches are generated from public geometry independently of the task goal.

Bounded route IK starts from the captured joint sensors for each candidate. A braking tail's IK starts from the current post-motion joint and EEF measurements and screens their corrective sweep to the continuing command reference, retaining the original captured collision surfaces, payload and clearance baselines. Each nearby Cartesian check continues inside a ±0.35 rad box around the preceding accepted joint solution, within the static joint limits. This local numerical search prevents accepting discontinuous elbow/wrist branches; it does not certify OSC convergence or claim infeasibility outside the box. IK caches include the incoming joint solution, and a new candidate resets to the measured joints.

## Smooth executor

Use **piecewise quintic splines with shared nonzero waypoint velocities and zero jerk at each original waypoint**, implemented with existing NumPy/SciPy. Ruckig is MIT and a viable alternative, but no new dependency is needed here; this choice allows inspection and re-screening of the exact blended Cartesian curve. Do not describe the result as globally minimum jerk: each original segment contains three quintic spans, with two internal knots providing enough degrees of freedom to constrain p/v/a/jerk at both ends. Internal span junctions are C4; original waypoints and rest boundaries are C3. `Trajectory.waypoint_times` identifies action waypoints; spline spans are not additional decisions. Opposite directions/contact boundaries use zero through velocity. Polynomial extrema bound velocity/acceleration/jerk; increase duration until limits hold.

Run at 20 Hz. Translate **vector** desired displacement into Panda OSC commands (`translation_action_scale_m=0.05`, `rotation_action_scale_rad=0.50`, verified in current Panda tests); do not independently clip XYZ.
